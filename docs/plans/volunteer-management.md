# volunteer-management — 봉사 관리 계획

## 담당자·API

- 담당자: 강민우
- `POST /api/v1/volunteer/{student_id}`
- `DELETE /api/v1/volunteer/{student_id}`
- `PATCH /api/v1/volunteer/{student_id}/count/increase`
- `PATCH /api/v1/volunteer/{student_id}/count/decrease`
- `GET /api/v1/volunteer`
- 당일 봉사자 지정·취소·조회 API (경로는 구현 때 정하고 이 문서에 반영한다)

## 구현

- 관리자만 봉사자 추가·제외·명단 조회
- 봉사 횟수는 앞으로 해야 할 횟수다(DEC-020). 봉사자 제외 후에도 남은 횟수 유지
- 목록의 `+`/`−` 클릭으로 1회 즉시 가감하고 조정 날짜 기록; 활동명은 비움
- 0회이면 `−`를 비활성화하고 서버도 음수를 거부
- 명단 추가·제외, 횟수 조정, 당일 봉사자 지정을 별도 동작으로 유지
- 사감이 매일 봉사자 명단에서 당일 봉사자를 지정·취소한다. 인원은 고정하지 않고 학생·운영일 단위로 중복 지정을 막는다.
- 지정할 때 같은 트랜잭션에서 `VOLUNTEER` 알림을 만들고, 취소하면 그 알림을 지운다. 지정·취소는 횟수를 바꾸지 않는다.
- 봉사를 마치면 기숙사 자치위원이 `−`로 따로 차감한다.
- 학생 본인 남은 횟수 조회는 `student-attendance.md`와 범위를 맞춘다.

## 계약 보완

- [ ] `student_id` path/body는 서버에서 존재 학생·관리자 권한을 검증한다.
- [ ] 같은 클릭의 재시도는 idempotency로 막고 새 클릭은 별도 1회로 처리한다.
- [ ] 증가·차감 API 모두 관리자 권한과 학생 존재 여부를 확인하고, 재시도 멱등성을 보장한다.
- [ ] 차감은 0회 미만이 되지 않도록 원자적으로 검증한다.
- [ ] 공지 CRUD API는 현재 명세에 없으므로 임의 구현하지 않는다. 당일 봉사자 지정 알림은 [알림 계획](notification.md)을 따른다.
- [ ] 당일 봉사자 지정 테이블(학생·운영일 unique)과 지정·취소·조회 API 경로를 정한다.

## 기준·검증

- 요구사항: `REQ-AUTH-003`, `REQ-COM-001~006`, `REQ-UI-004~006`
- 수용 시나리오: `ACC-AUTH-003`, `ACC-COM-001~006`, `ACC-UI-004~006`
- 일반 학생이 봉사 명단·타인 횟수·관리 mutation을 호출하지 못하게 한다.
- 추가 중복, 제외 후 재추가, 두 번의 새 클릭, 동일 요청 재전송을 구분한다.
- 봉사 횟수와 당일 봉사자 지정은 08:00 출석 정리 때 삭제하지 않는다.
- 지정·중복 지정·취소 때 알림이 한 번 생기고 취소 후 사라지는지 확인한다.
